# Pinned HTTPS signing-key document source

Reviewed 2026-10-14 UTC. `CustomerHttpsJwksDocumentSource` implements the isolated key-cache source contract, but is **unregistered**. No production listener, current HTTP/stdio composition, OAuth issuer, owner authority, Slack integration or shared Goblin service changes. Tests use mocked transport, not live DNS/TLS/provider traffic.

## Official API evidence

[OpenAI authentication](https://developers.openai.com/plugins/build/auth) requires resource-server signature/issuer/audience/lifetime/scope checks with authorization-server signing keys. Key retrieval does not authorize Work or prove public-plugin/Sign in with ChatGPT eligibility.

[Microsoft's ResponseHeadersRead documentation](https://learn.microsoft.com/en-us/dotnet/api/system.net.http.httpcompletionoption?view=net-10.0) explains that ordinary HttpClient timeout and content-buffer limits do not cover subsequent body streaming. This source passes one linked cancellation deadline through send, stream creation and every body read, then explicitly limits streamed bytes.

[SocketsHttpHandler redirect documentation](https://learn.microsoft.com/en-us/dotnet/api/system.net.http.socketshttphandler.allowautoredirect?view=net-10.0) says automatic redirects are enabled by default and false returns redirect responses to the application. This component explicitly disables them and accepts only status 200; it does not retry/re-authenticate or fetch Location. Cookie and credential settings follow the [cookie](https://learn.microsoft.com/en-us/dotnet/api/system.net.http.socketshttphandler.usecookies?view=net-10.0) and [credential](https://learn.microsoft.com/en-us/dotnet/api/system.net.http.socketshttphandler.credentials?view=net-10.0) APIs.

## Implemented experimental policy

- Construction validates a customer-configured HTTPS JWKS URI on the issuer origin, without userinfo/query/fragment/controls/backslashes, bounded at 2048 UTF-16 characters. It does not fetch or discover. Each source instance pins that exact URI's original string; a different runtime URI is denied before sending, even a trailing-slash variant. Token-selected URLs/keys are never inputs.
- The source owns and disposes a dedicated HttpClient/SocketsHttpHandler. No externally shared credentialed client is accepted. Automatic redirects, cookies, proxy use, preauthentication and decompression are disabled; credentials are null. System TLS chain/hostname validation is retained, without a custom validation bypass or client certificate. Private customer PKI requires legitimate system trust configuration, not insecure acceptance. Explicit proxy/customer client-certificate scenarios are not supported here.
- One GET with JSON/JWK-set Accept headers and no body, bearer, Cookie or proxy credentials. Connections have a five-second connect limit, two-per-server cap and one-minute pooled lifetime; response headers have an eight-KiB handler limit. These are experiment policy, not universally compatible provider requirements.
- A five-second linked deadline covers header send and body reads, preserving caller cancellation and sanitizing internal timeout/transport/content failures. No wrapper retry or background task. Actual cancellation/connection cleanup still depends on the standard handler/OS; mock tests do not establish network timing or TLS behavior.
- Accept only 200, unchanged effective request URI, JSON or JWK-set JSON content type, absent/UTF-8 charset and no content encoding. Reject declared bodies over 32 KiB before reading. A fixed 32-KiB-plus-one array reads only that many bytes, including unknown-length bodies; the extra byte proves overflow. Empty bodies/invalid UTF-8 deny. Stream and response disposal happen on success, rejection, provider failure and cancellation. JSON/key validation is still the separate cache's responsibility.

The internal handler constructor is available only to the named friend test assembly and is not a supported application composition surface. Mock handlers cannot establish the real SocketsHttpHandler's TLS/redirect behavior; separate settings assertions check the configured defaults without connecting. Hostname/DNS/IP/egress controls remain customer deployment responsibility. A pinned customer URI is not proof that its discovery metadata or host is trustworthy: owners must approve source configuration independently.

## Verification and data boundaries

Focused tests exercise the real source against mocked handlers/nonseekable chunked streams: exact credential-free request, media types, runtime pin/unsafe construction, redirect/failure/effective-URI denial, declared/chunked byte limits, malformed UTF-8/content, disposal, cancellation, real five-second stalled-send/stalled-body deadlines and a concurrent cold-cache load with one retrieval. Ephemeral public RSA material remains in memory. No real HTTP request, provider discovery/token flow, database read, TLS handshake or ChatGPT/Slack connection was performed.

If adopted, JWKS requests/public-key responses go directly between the customer's Goblin runtime and its customer-owned identity provider. The source receives no bearer, password, private signing key, Work record or customer OAuth token. There is no Goblin-operated cache/proxy/auth server. OpenAI necessarily handles connector codes/access/refresh tokens and selected tool fields when connected; Slack handles selected messages/events separately. Authoritative history/configuration and private credentials remain customer-owned, but do not promise selected platform data/token copies remain exclusively on-premises.

The isolated [owner-authorized invalidation prototype](KEY-CACHE-INVALIDATION.md) clears cache generations but is not a provider key denylist or retroactive read revocation. Next: generation-bound verification leases, still without production routes or automatic grants. The ten-minute default key-removal window, same-kid replacement, ingress rate limits, provider resource/PKCE/callback enforcement, durable local permissions and live TLS/provider validation remain gates. Do not retry recorded live-auth/database/formatter blockers without changed capability evidence.
